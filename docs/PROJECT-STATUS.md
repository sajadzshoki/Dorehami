## 1. What Phase 0.1 resolved (with evidence)
- **Version compatibility (technical, evidence-based):** npm registry metadata checked 2026-10-14 — Nuxt 4.6.1 (Node `^22.22.3 || ^24.15.0 || >=26`), @nuxt/ui 4.11.3 on Tailwind v4 (4.3.3), @nuxtjs/i18n 10.6.0, drizzle-orm 0.45.4 (`pg >=8` peer; pg 8.23.1), drizzle-kit 0.31.11, TypeScript 5.9.3 recommended over the new 7.x major. Official docker-library tree maintains PostgreSQL 14–19; **PG 17/18 recommended**, exact minor/digest pinned at Phase 1 bootstrap. Full table: ADR-0001/0003. These are ceilings from metadata, not a lockfile — Phase 1 re-verifies on bootstrap day.
- **No-custom-Dockerfile production workflow:** ADR-0018 now specifies Option A (CI assembles a Dockerfile-less OCI image via `crane append` onto the digest-pinned official Node 24 image; VPS pulls by digest), Option B fallback (verified tarball + read-only bind mount), and Option C (relax the constraint) explicitly gated on founder approval. A Phase 1 spike proves Option A before it is relied on (AC-AUDIT 25).
- **Migration failure/recovery:** backup → one-shot migration from the same image → app rollout; failure halts the deploy with the old version serving; forward-fix or restore; proof drill is a Phase 1 acceptance item (ADR-0004, AC-AUDIT 26).
- **Authorization/privacy:** normative permission matrix (DOMAIN-MODEL §11) and suspension/blocking/deletion semantics (§10, §12); attendee-list ambiguity resolved (never anonymous; `public` = authenticated only).
- **Event edge cases:** concurrent capacity, retries, material-change/reschedule notifications, series edits never moving registered occurrences, DST gap/fold rules, organizer suspension/deletion, community archival → events become standalone (DOMAIN-MODEL §10, ADR-0007).

## 2. Contradictions & risks found in the Phase 0 audit (all fixed or explicitly flagged)
1. `events.organizer_id` FK target was ambiguous (users vs organizer profile) → now `organizer_profiles(user_id)` everywhere (ERD, DOMAIN-MODEL).
2. Attendee visibility `public` conflicted with “never anonymous beyond counts” → resolved in DOMAIN-MODEL §11.
3. ERD diagram showed reactions/reports/media as loosely “polymorphic” while the text preferred explicit FKs → explicit nullable FKs + exactly-one-target checks, diagram corrected.
4. Slug policy said “unique per locale” while events carry a single content locale → single stable ASCII slug (resolves Q-13 as a technical recommendation, D-08).
5. `event_occurrences` could disagree with its series (`series.event_id ≠ occurrence.event_id`) and organizer edits had no lost-update protection → composite consistency rule + `revision` optimistic concurrency (`REVISION_CONFLICT`).
6. Organizer suspension/deletion and community deletion had no defined effect on events/registrations → DOMAIN-MODEL §10.
7. Rescheduling was unspecified (silent time edits would strand registrants) → material-change notification rules (ADR-0007, AC-AUDIT 29).
8. Blocking was simultaneously “recommended MVP”, “Open”, and absent from the ERD → single proposed design (DOMAIN-MODEL §12, `user_blocks` marked Proposed) pending founder decision D-05.
9. ADR-0016's “audit retained indefinitely” pre-judged a legal question → retention periods stay **open** (D-06); no compliance is claimed anywhere.
10. Threat model lacked supply-chain and block/suspension-bypass coverage → T-23, T-24 added.
