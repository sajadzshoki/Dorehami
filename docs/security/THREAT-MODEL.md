# Threat Model — Dorehami

Method: asset/actor/path analysis per feature area; severity = likelihood × impact (Critical/High/Medium/Low). Every threat has a testable control — the "Verification test" column feeds [ACCEPTANCE-CRITERIA](../quality/ACCEPTANCE-CRITERIA.md) and phase test plans. Actors: anonymous internet user (A), authenticated user (U), malicious organizer/member (M), external attacker with stolen credentials (X), abusive automated client (Bot).

| # | Threat (asset / actor) | Path | L×I = Sev | Preventive controls | Detective controls | Verification test | Priority |
|---|---|---|---|---|---|---|---|
| T-01 | Account takeover via OTP abuse/brute force (accounts / A,Bot) | Guess OTP, credential-stuff password login, abuse recovery | M×H = **High** | 6-digit+ OTP, 5-min expiry, ≤5 attempts, per-phone/IP rate limits, resend cooldown, optional-password policy §Baseline-2, login alerts (Provisional) | Auth failure metrics, anomaly alerts on OTP request spikes | Automated brute-force test hits lockout; expired/replayed codes rejected | P1 (Phase 3) |
| T-02 | OTP replay/reuse/bypass (sessions / A) | Reuse consumed code, race verify, skip verify via direct API call | M×H = **High** | Single-use challenges consumed transactionally; hashed codes; purpose binding; session only issued inside verify transaction | Audit of verify anomalies | Replay test: second verify of same code fails; concurrent verify yields ≤1 session | P1 |
| T-03 | Session fixation/theft, incomplete logout (sessions / X) | Fixated cookie, XSS token theft, logout only clearing cookie | M×H = **High** | Server-side sessions, opaque HttpOnly Secure SameSite cookies, rotation on login/privilege change, logout revokes server-side, session list + revoke-all in settings (Provisional) | `last_seen` metadata; user-visible session list | Logout then replay old token → 401; login rotates token | P1 |
| T-04 | BOLA/IDOR (all resources / U,M) | Change IDs on registrations, posts, messages, admin routes | H×H = **Critical** | Server-side per-resource authorization on every handler (API-CONTRACTS §5); opaque IDs; deny-by-default | Authorization-failure logging | Per-endpoint two-user test suite: every cross-user access → 403/404 | P1, every phase |
| T-05 | Privilege escalation to organizer/admin (platform / U) | Forge role fields, mass-assignment, direct admin route calls | M×C = **Critical** | Capabilities changed only by dedicated server flows; strict input schemas (no role fields accepted); admin grant via CLI + audit; admin routes check platform role server-side | AuditLog on every capability change; alert on admin grants | Attempt role injection in profile/event payloads → ignored+logged, tests pass | P1 |
| T-06 | Attendee data exposure (PII / M,A) | Organizer or public page leaks attendee lists/phones | H×H = **Critical** | Attendee visibility setting enforced in queries; organizers see display names only (never phone numbers); public pages show counts only | Access logs sampled; privacy test fixtures | Tests: anonymous/participant/organizer each receive exactly allowed fields | P1 (Phase 4) |
| T-07 | Profile/DM exposure (privacy / A,U) | Guess conversation IDs, scrape profiles | M×H = **High** | Participant check on every message read/write; profile visibility enforced server-side; no DM content in notifications beyond policy | 403 pattern logging | Non-participant conversation access test → 403; hidden profile test | P1 (Phase 5) |
| T-08 | SQL injection / malicious input (DB / A,U) | Crafted filters, search `q`, sort params | M×H = **High** | Drizzle parameterized queries only; sort/filter whitelists; schema validation at boundary; no raw SQL string building | DB error alerting (sanitized) | Injection payload corpus in API tests; code-review rule: no string-concatenated SQL | P1 |
| T-09 | XSS (content / M) | Script in posts, descriptions, links, display names rendered to others | H×H = **Critical** | Vue auto-escaping; never `v-html` on user content (rich text, if ever, via sanitized renderer — MVP plain text, Provisional); URL scheme whitelist (`https:` only); CSP headers | CSP report endpoint (Phase 8) | Stored-XSS payload tests on every user-content field; CSP present in headers test | P1 |
| T-10 | CSRF / CORS / cookie misuse (sessions / A) | Cross-site POSTs with victim cookie | M×H = **High** | SameSite=Lax (Strict where flows allow), CSRF token or strict Origin/Referer check on mutations (Nitro config Phase 1), CORS allowlist = own origins only | Origin-mismatch logging | Cross-origin mutation test → 403; CORS preflight test | P1 (Phase 1) |
| T-11 | SSRF (server / U,M) | Event online-URL/image-from-URL fetched server-side, metadata endpoint probing | M×M = **Medium** | MVP: **no server-side fetching of user URLs at all** (links stored, never fetched; images only via upload) — removes the class; any future fetcher needs allowlist + private-range blocking | Egress logging if fetcher ever added | Code/architecture test: no fetch of user-supplied URLs; config review | P2 |
| T-12 | Malicious uploads / MinIO exposure (media, infra / U,Bot) | MIME spoofing, oversized/polyglot files, public bucket listing | H×H = **Critical** | Size caps, content-sniffed type whitelist (images only in MVP), server-generated object keys, private buckets, short-lived signed URLs, AV scan (Provisional Phase 8 if available), no SVG uploads (or sanitized) | Upload rejection metrics; bucket-policy check in deploy runbook | Upload spoofed/oversized/SVG tests rejected; anonymous bucket listing denied; signed URL expiry test | P1 (Phase 4/2 media) |
| T-13 | SMS abuse / provider cost (budget / Bot,A) | OTP request flooding many numbers | H×M = **High** | Per-phone/IP/device rate limits + cooldowns, CAPTCHA after threshold (Provisional, privacy-reviewed), daily budget alert | Provider spend/request dashboards, alerts | Load test: flood capped, `429` + cooldown enforced | P1 (Phase 3) |
| T-14 | Spam, bot registrations, report abuse (integrity / Bot,M) | Mass signups, fake registrations filling capacity, false reports | H×M = **High** | Auth required to register; rate limits; publication review for low trust; report rate limits; admin tooling to bulk-remove | Registration-velocity metrics per event/organizer | Bot-simulation test hits limits; capacity cannot be filled by one account (1 reg/user) | P2 |
| T-15 | Capacity race conditions (integrity / U,Bot) | Parallel registrations for last seats | M×H = **High** | Transactional check+insert with row lock/atomic conditional update; partial unique index (ADR-0008) | `registered_count` reconciliation job/test | Concurrency test: 50 parallel requests for capacity 10 → exactly 10 confirmed | P1 (Phase 4) |
| T-16 | Recurring-event abuse (integrity/DoS / M) | Absurd rules (minutely × years) exhausting storage/queries | M×M = **Medium** | Rule validation: min interval, max occurrences (Provisional ≤ 366/series), materialization window 6 months, per-organizer series caps | Series-size metrics | Fuzz recurrence rules → invalid rejected, occurrence count bounded | P2 (Phase 4) |
| T-17 | Secrets/PII in logs (confidentiality / X,insider) | OTP codes, tokens, phone numbers logged | M×H = **High** | Structured logging with a redaction allowlist; never log bodies of auth/messaging endpoints; log `requestId`, IDs, not content | Log-scan CI check for patterns; manual review | Grep-based log test in CI; attempted OTP in payload absent from logs | P1 (Phase 1) |
| T-18 | Unauthorized admin actions/config change (platform / U,X) | Stolen admin session, missing audit, silent setting changes | L×C = **High** | Admin role server-enforced; sensitive actions confirm + audit (actor/action/target/minimal metadata); `system_settings` changes audited; admin session shorter idle timeout (Provisional) | Append-only AuditLog review; alerts on admin grants | Non-admin admin-route tests → 403; every admin mutation produces exactly one audit row | P1 (Phase 7) |
| T-19 | Secret exposure via Git/images/logs (infra / A,insider) | Committed `.env`, secrets in image layers or docs | M×C = **Critical** | `.gitignore` + secret scanning CI, env-only secrets, image-layer secret scanning (ADR-0018 E-1) reduces layer risk, docs contain variable *names* only | Pre-commit/CI secret scan; repo history scan before first deploy | Secret-scanner passes on repo; simulated leaked key in test branch is caught | P1 (Phase 1) |
| T-20 | DoS / expensive endpoints (availability / Bot) | Search/filter abuse, huge pages, image bombs | M×M = **Medium** | Pagination caps, query timeouts, rate limits on search/auth/upload, image variant generation bounded/async (Phase decision) | Latency/error dashboards | Load test on discovery endpoints within perf targets at agreed concurrency (Phase 8) | P2 |
| T-21 | Notification abuse / unsafe links (users / M) | Phishing links in notifications, notification spam | M×M = **Medium** | Notifications carry internal validated paths only (no user-supplied URLs rendered as links), per-type preferences, rate-limited triggers | Report flow covers notification abuse | Test: crafted payload cannot inject external link into notification rendering | P2 (Phase 6) |
| T-22 | Mock/dev functionality in production (integrity / A) | Mock SMS accepts `123456`, debug routes shipped | M×C = **Critical** | Provider selection by env with production fail-fast validation; mock adapter excluded/blocked when `NODE_ENV=production`; no debug routes in prod build; startup config validation refuses unsafe combos | Startup self-check logs provider mode (name only); deploy checklist item | Production-mode boot with mock/missing SMS config **fails**; fixed-code OTP rejected in prod-mode test | P1 (Phase 1/3) |

| T-23 | Blocked-user circumvention & suspension bypass (users, integrity / M, suspended U) | Blocked user creates a new conversation path or keeps sending in an old one; suspended organizer keeps acting through an already-issued session or stale capability cache | M×M = **Medium** | Block + suspension enforced server-side at initiation, send, and every privileged mutation (not just at login); suspension revokes sessions immediately; capability checks read authoritative state, never cached claims (DOMAIN-MODEL §10–12) | Denied-send/suspension-action logging | Tests: after block, initiation and sends fail generically; after suspension, existing session tokens and event-mutation calls are rejected | P2 (Phase 5/7; **if D-05 approved** — otherwise report-only subset applies) |
| T-24 | Production-image supply-chain tampering (infra / external attacker, compromised CI) | Floating base tags, unverified artifact substitution, or tampered CI output reaches the VPS | L×H = **High** | App image built by the ADR-0018 selected workflow (standard Dockerfile by founder-approved default; Dockerfile-less only if it passes the same E-1 criteria) from base images **pinned by digest**, no secrets in any image layer (scanned), image referenced by digest in production Compose, registry write access limited to CI, artifact digest recorded per release; fallback Option B requires checksum-verified tarballs | Registry/CI audit logs; deploy-time digest recorded in release notes | Phase 1 experiment E-1: altered digest/checksum is rejected; deploy refuses a floating tag; secret scan of image layers passes | P1 (Phase 1) |

## Residual risks & notes

- SMS delivery itself (SIM swap, interception) is an inherent OTP weakness: mitigated partially by optional password + session controls; passkeys/WebAuthn are post-MVP candidates (recorded, not promised).
- Privacy/legal retention periods (reports, audit, deleted content) need legal validation (D-06) before Phase 8 sign-off.
- Severity assumes an internet-facing production VPS; re-score after Phase 1 deployment design.
